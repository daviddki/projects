Piping Component Classifier

Internship project · Huen System, Seoul, South Korea

Company
Huen System

Date
Summer 2026
Tools

Huen System builds Revit-based software for BIM, and EZ-ISO is its tool for turning piping models into isometric drawings. To do that well, the software has to know what each piece in a model actually is: a valve, a flange, a fitting, a support. Family and type names are unreliable across projects and languages, so my team built a machine learning classifier that identifies components from their shape and their connectors instead.

The code and data belong to the company, so this page covers the approach and the results, not the implementation.

  • Component group95.7%5-fold accuracy, 12 classes, 3,815 components
  • Valve subtype86.8%5-fold accuracy, 6 classes, 552 valves
  • Training data180BIM projects, labeled by domain experts

How it works

Input
Geometry and connector features pulled from each Revit family
→
Stage 1(Component group)
12 classes: fitting, flange, valve, support and more
→
Stage 2(Valve subtype)
Only for parts predicted as valves: ball, gate, globe, butterfly, check, basic
  1. Classify by shape, not by name The models never see family names, type names or category text. Those change with the project, the firm and the language, and I wanted the classifier to keep working on models it had never seen. Inputs are the size and proportions of the part, how much of its surface is flat, cylindrical or revolved, and how its connectors are placed.
  2. Gradient-boosted trees Both stages use LightGBM on tabular features, evaluated with stratified 5-fold cross-validation. Trees handle the mix of size, ratio and count features well, and they train in seconds, which made it easy to iterate on features.
  3. A separate valve model Valves are the hardest group to tell apart, so I split them into their own module with its own feature set, class report and saved models. Only parts that stage 1 calls a valve go through it. Keeping it separate means the valve model can change without retraining the whole pipeline.
  4. Feature engineering I added eight features: the fraction of surface area that is planar, cylindrical and revolved, bounding-box volume, centroid offset, density, surface-to-volume ratio and a connector radius ratio. Together they describe how a part is built rather than just how big it is.

Results

Accuracy on the component group task went from 88.3% in the first version (19 models, leave-one-out) to 94.8% after scaling to all 180 projects, and to 95.7% with the added features. All numbers below come from the final saved models.

Limitations

  • Optimistic validation. Folds are stratified by class but not grouped by project, so parts from the same project can land in both training and validation. Accuracy on a brand-new project is likely lower, and grouped cross-validation is the next thing I would run.
  • Small changes are within noise. The gain from the added features (94.8% to 95.7%) is about the size of the fold-to-fold spread (±0.6 points), and I did not run a controlled ablation, so I can't credit it to the features alone.
  • Rare classes. Accessories, unknown parts and globe valves have too few examples for stable scores. More labeled data would help most here.

Component group: 95.7% ± 0.6 across folds. Valve subtype: 86.8% ± 4.3 across folds (sample standard deviation).
